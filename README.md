**把一句旅行愿望，变成一份日期、交通、住宿、接驳和费用都能对得上的最终行程。**

TripChord 是一个面向中文自由行用户的本地优先 Multi-Agent 旅行决策产品。用户只需要说明想去哪里、哪段时间方便、准备玩几天、同行人数和在意的体验，TripChord 就会展开可行日期，同时查询已连接的交通、住宿和接驳来源，算清这趟旅行所有人的费用，最后只给出一份建议。

它的核心目标很直接：**先找到真正能走、也符合用户要求的行程，再从本次确实查到且能够公平比较的报价中，选择总花费最低的一份。** 用户明确提出的酒店品质、位置、早餐、行李或是否接受中转等要求也会进入选择，而不是被最低价格覆盖。

当前版本是 **1.0.0 / Beta**。核心规划、偏好记忆和自然语言修改已经形成闭环；它仍是本地开发者版本，不代表签名安装包、生产稳定性、商业采用或全平台覆盖。

## 从一句需求到一个答案

例如：

> 8 月 20 日到 9 月 10 日之间，从杭州去马尔代夫玩 4–8 天，2 位成人。住宿不要简陋或偏僻，希望住得舒服，也别太贵。

TripChord 会在后台完成这些工作：

1. 理解日期范围、旅行天数、同行人和住宿偏好。
2. 用程序生成全部合法日期组合，再按本次查询预算并行搜索。
3. 同时读取已连接的机票、酒店和接驳来源；平台失败与真正无票、无房会被分别记录。
4. 核对报价对应的具体航班、房型、日期、人数、税费和币种。
5. 把交通、住宿与接驳组合成完整行程，排除时间接不上、住不下或不符合要求的方案。
6. 在可行方案中比较总费用和用户偏好，并由程序重新核对后只发布一份结果。
7. 用户继续用中文修改行程；只重算受影响的部分，新方案不成立时保留原方案。

同行人数不是固定的“两位成人”。系统按每次需求计算同行总价；只有来源能够明确支持对应的成人、儿童、婴儿和房间组合时，报价才会进入比较。

## 真实来源结果与可复现案例

仓库保存了 2026 年 8 月的两段只读来源结果，并用一条离线验收链将它们串起来：一段负责灵活日期探索，一段负责固定日期的完整规划。日期探索生成了 85 组合法组合，实际并行精查其中 3 组，真实查询耗时 254.557 秒；它本身没有发布完整行程。下面的安排来自后来对其中同一日期完成的固定规划，不能倒推成前一次日期探索已经成功发布方案。

| 行程部分 | 最终安排 |
| --- | --- |
| 去程 | 2026-09-03 21:45 杭州出发，JD5907 + JD455；09-04 12:20 抵达马累 |
| 住宿 | 09-04 至 09-09，Kaani Beach Hotel，市景豪华阳台房，含早餐、免费取消；携程双人含税总价 ¥2,485 |
| 接驳 | 09-04 15:25 机场至 Maafushi；09-09 09:30 Maafushi 至机场；按当日参考汇率估算共 ¥806.47（iCom 公开基础价合计 USD 120） |
| 返程 | 2026-09-09 14:20 马累出发，JD456 + JD5908；09-10 09:25 抵达杭州 |
| 费用 | 机票与住宿已确认小计 ¥10,687；按当日参考汇率计入接驳后约 ¥11,493.47 |

接驳税费仍未知，所以 ¥11,493.47 是参考估算，不是锁定的结算价。住宿位置只依据页面明确地址及附近潜水、水上活动服务点判断为不偏僻，不额外声称靠近码头或市中心。本次只有携程返回了满足同一住宿要求的可比较报价，因此它证明的是“当前合格结果中的选择”，不是全网最低价。

同一份保存数据还复现了自然语言修改：

- “酒店换成海景房，航班和接驳保持不变”——只替换住宿，海景房 ¥2,605，比原房型增加 ¥120；航班和两段接驳完全不变。
- “换一家酒店”——其他酒店缺少足以证明位置合适的信息，修改停止，原方案保留。
- 同时修改出发和返程日期——升级为完整重算；若新日期没有形成合格方案，原方案不会被覆盖。

离线复现整条链约需 0.21 秒；这个数字只代表本地重算速度，不能代替平台实时查询耗时。详见 [1.0 验收记录](docs/v1.0-acceptance.md)。

## 系统怎样工作

```mermaid
flowchart LR
  A[自然语言需求] --> B[日期空间与查询计划]
  B --> C[交通、住宿、接驳并行查询]
  C --> D[报价、人数与产品身份统一]
  D --> E[完整行程候选]
  E --> F[Multi-Agent 选择、风险与修改建议]
  F --> G[程序复算与最终发布]
  G --> H[一份最终行程]
  M[用户确认的长期偏好] --> B
  G -.价格与库存不写入记忆.-> M
```

TripChord 不让多个模型自由聊天。每个角色只看到完成自己工作所需的信息，使用限定工具，并输出可以被程序检查的结构化结果。一个角色存在于架构中，也不代表每次运行都要调用一次模型；没有真实取舍价值时会直接跳过。

| 角色 | 在一次规划中负责什么 |
| --- | --- |
| Context / Memory Curator | 理解当前需求，读取或提出长期偏好；当前请求始终优先，价格与库存不能进入长期记忆 |
| Query Strategist / Search Supervisor | 在程序已经生成的日期空间内安排搜索顺序、来源和并行节奏，不能删除日期或扩大平台权限 |
| Evidence Arbiter | 判断不同页面是否对应同一航班、房型或班次，以及价格是否真的可以比较 |
| Candidate Curator | 在完整可行的候选中权衡总费用和用户明确偏好；没有真实权衡时不调用模型 |
| Risk Critic / Repair Strategist / ReCritic / Event Diagnoser | 发现中转、入住、位置等旅行风险，提出修改范围，并独立复查修改是否带来新问题 |
| Orchestrator / Explanation | 汇总结构化结论并组织中文说明；不能新增报价、航班、房型或绕过最终检查 |

日期生成、人数换算、金额、税费、产品身份、行程衔接、修改执行和最终复查始终由确定性程序负责。完整角色、输入合同与工具权限见 [系统架构](docs/architecture.md)。

## 关键设计取舍

| 问题 | TripChord 的选择 |
| --- | --- |
| 灵活日期会产生大量组合 | 程序生成完整合法空间，固定工作池并行精查；结果必须说明本次究竟查了多少，模型不能偷偷省略日期 |
| 平台价格写法不同 | 先统一具体产品、日期、人数、税费与币种，再比较这趟旅行所有人的总费用 |
| LLM 灵活但可能编造事实 | 模型只负责语言理解和有限候选中的判断；所有事实和最终发布都能由程序拒绝 |
| Multi-Agent 容易拖慢 | 角色按需要触发；当一个候选在用户关心的权益上不差且更便宜时，跳过无价值的模型调用 |
| 用户希望被记住 | 只保存用户确认过的稳定偏好，并带作用范围、版本、撤销和过期；实时价格、库存和班次永不进入 RAG |
| 用户想继续修改 | 先识别受影响范围，只重查对应部分；修改后的完整行程必须再次通过独立复查 |
| 是否迁移 LangGraph | 当前类型化运行时已经承担任务图、并发、工具权限、恢复和发布合同；只有独立试验能证明复杂模型子流程确实受益时才局部引入 |

平台能力通过带类型合同的来源适配器和本机 Chrome Companion 接入。当前没有把外部 Skill、插件或 MCP 当作产品运行依赖；新增平台首先要成为可测试、可停用、不会绕过价格与权限检查的工具。

## 1.0 已完成的范围

- 中文自然语言需求进入统一规划链；
- 灵活日期组合生成、并行查询、去重和实际覆盖说明；
- 交通、住宿、接驳的产品身份与同行总价统一；
- 只输出一份最终行程，并展示去程、住宿、接驳、返程和人民币费用；
- 住宿品质、位置、早餐、行李与是否接受中转等明确要求进入选择；
- 用户偏好可保存、撤销和过期，实时旅行事实与记忆隔离；
- 自然语言修改、受影响部分重算、失败后原方案保留；
- 长任务状态、已完成日期、浏览器任务和短期结果具备本机持久化路径；
- 一条由保存真实来源数据驱动、可重复运行的端到端验收链。

1.0 之后继续成熟化的内容包括普通用户安装与升级封装、手机端、减少浏览器标签或改为无头查询、更多平台与目的地、混合成人与儿童场景的持续真实验证，以及更长时间的真实平台成功率和性能观测。

## 本地运行

需要 Python 3.12 或 3.13、Node.js 22 和 [uv](https://docs.astral.sh/uv/)。

```bash
git clone --branch productization/v1.0 https://github.com/Oxygen56/TripChord.git
cd TripChord
uv run python scripts/tripchord_launcher.py check
uv run python scripts/tripchord_launcher.py setup
uv run python scripts/tripchord_launcher.py wizard
```

分别启动本机 API 与 Web 界面：

```bash
uv run python scripts/tripchord_launcher.py api
uv run python scripts/tripchord_launcher.py web
```

访问 `http://localhost:5173`。默认配置不访问真实平台，也不调用外部模型。实时网页查询需要用户在自己的 Chrome 中登录对应平台，为 [Chrome Companion](apps/browser-companion/README.md) 授予指定域名的只读权限，并配置模型服务；TripChord 不读取 Cookie、密码或 Chrome 用户目录。

复现 1.0 核心验收：

```bash
env -u TRIPCHORD_FORMAL_MODEL_ROLE .venv/bin/pytest -q -s apps/api/tests/test_v1_acceptance.py
```

## 能力边界

- 只比较本次真正查到且能公平比较的平台，不宣称全网最低。
- 保存案例是历史来源回放，不是当前价格、库存或可订承诺。
- 平台登录、验证码、网络和页面结构变化仍可能让某个来源失败；失败不会被解释成无库存。
- 混合成人、儿童和婴儿只有在来源给出完整同行报价时才能参与选择，当前还没有同等级真实端到端覆盖。
- `1.0.0 / Beta` 不代表签名安装包、跨机器生产稳定或真实商业采用。
- TripChord 永远不下单、付款、接受条款、使用优惠券、锁定库存、修改或取消预订。
