# TripChord 1.0 桌面核心验收

TripChord 1.0.0 是一个本地优先的旅行决策产品：它把中文旅行需求转换成日期组合，读取已连接的只读来源，统一人数与价格口径，组合航班、住宿和接驳，只发布一份通过程序复验的行程；关键事实不足时保留原方案或停止发布。这个版本代表桌面核心功能已经交付，不代表已经提供签名安装包、生产稳定性或商业采用。

## 产品解决什么

普通旅行搜索会分别展示机票、酒店和船班，用户仍要自己判断日期、人数、机场、入住区间、接驳缓冲与总费用是否一致。TripChord 把这些约束放在同一条链上：

1. 解析自然语言中的日期窗口、停留时长、同行人和住宿偏好；
2. 由程序生成全部合法日期组合，再按运行策略并行精查其中一部分或全部组合；
3. 从已连接平台和官方公开来源读取结构化结果，保留抓取时间与失败边界；
4. 统一单人价、所有人的总费用、每晚价、税费和币种，不能公平比较的金额不参与选择；
5. 组合交通、住宿与接驳，先排除违反用户明确要求的方案，再选择一份最终方案；
6. 用户用中文提出修改时，只重查或重算受影响部分；新方案不成立时原方案不变；
7. 永远不下单、付款、接受条款、锁库存、修改或取消预订。

## 可复现验收链

验收使用 2026-08-21 保存的真实只读来源结果，整个回放过程不访问 OTA，也不刷新价格、库存或抓取时间。运行：

```bash
env -u TRIPCHORD_FORMAL_MODEL_ROLE .venv/bin/pytest -q -s apps/api/tests/test_v1_acceptance.py
```

这条命令从原始中文需求开始，依次验证：

- 需求被解析为杭州至马尔代夫、2026-08-20 起、最晚 2026-09-10 回到杭州、4–8 天、2 位成人、1 间房；在领域模型中对应 3–7 晚；
- 程序生成 85 个合法日期组合。保存的真实运行按当时策略实际精查 3 组，三组在 20 毫秒内同时启动；这不等于真实查询了完整 85 组；
- 20 条携程住宿观察被当前代码重新整理，满足位置、房型、早餐、取消和所有人总费用要求的有 8 个可组合候选；
- 唯一确定性赢家是 Kaani Beach Hotel 的市景豪华阳台房，因此不调用候选策展模型；
- 已确认的稳定早餐偏好可以用于本次规划，保存的实时价格不能作为后续旅行的当前价格，也没有改变本次回放金额；
- “酒店换成海景房，航班和接驳保持不变”只替换住宿；
- “换一家酒店”因另一家住宿缺少足够的位置便利证据而停止，原方案不变；
- 双日期全局修改未形成可发布完整方案时停止，原方案不变。

本机最近一次离线回放墙钟约 **0.21 秒**。保存的三日期真实查询墙钟为 **254.557 秒**；两者分别是本地重算和历史平台查询，不能混为一次实时性能数据。

## LLM、Agent 与确定性程序如何分工

TripChord 是多角色协作架构，但不是让一群大模型自由讨论。角色表示职责和权限，是否调用 LLM 由当前任务决定。

| 环节 | 当前职责 |
| --- | --- |
| 需求理解 | 先用确定性解析；仅在关键语义仍不明确时才请求模型提案，程序仍负责冲突与日期校验。 |
| 查询与来源 | 程序生成日期、并行任务、权限、超时与失败状态；本机 Chrome 只读连接扩展和官方公开接口负责采集。 |
| 报价与候选 | 程序统一人数、税费、币种、产品身份和衔接，并生成有界候选。 |
| 方案选择 | 只有候选之间确实存在价格与体验取舍时才调用模型角色；若一个候选在用户声明的体验上不差且所有人的总费用更低，则由程序直接选择。本次回放没有调用模型。 |
| 风险、修改与发布 | 角色可以提出建议，但修改由程序执行；程序会在修改前后分别核对所有必须满足的要求，并决定结果能否发布。未实际调用的角色不会被描述为参与。 |
| 解释与记忆 | 解释只能使用已经核对的信息；只有用户明确确认的稳定偏好可长期保存，实时价格、余位和班次不能进入长期记忆。 |

外部 AI 接入目前不是产品运行依赖。平台能力通过专用连接模块和浏览器只读工具接入；模型即使启用，也只能读取获准信息并提出建议，不能改价格、日期、权限或发布结果。模型供应商返回的费用信息不完整，因此不能把记录中的 0 美元估算解释为免费。

## 并行与长期任务取舍

- 合法日期全集由程序生成；查询预算可以让一次运行只精查部分组合，但必须公开实际覆盖范围。
- 日期组合并行，航班、住宿和接驳来源也可并行；相同查询使用稳定指纹去重，同一失败不会反复撞击平台。
- 平台登录、验证码、页面结构变化和持续搜索失败分别记录；未查询或技术失败不等于无库存。
- 长任务、浏览器租约、短期报价复用和结果投影已有持久化路径，但当前验收没有声称跨机器生产稳定。
- 本次同行人是 2 成人；成人-only 的任意 N 人由同产品 1/N 价格对照支持。儿童或婴儿只有在来源明确给出完整同行结构总价时才可进入排名，否则停止。

## 1.0 验收结论

桌面核心 1.0 已具备：自然语言入口、灵活日期空间、已连接来源的只读查询链、人数价格口径、完整组件组合、住宿品质与位置硬门、人民币方案投影、偏好记忆隔离，以及中文局部修改和失败保护。上述链路已有一条保存真实来源数据驱动的可复现端到端回放。

仍未完成的后续工作包括：普通用户签名安装与升级封装、手机端、减少或无头化浏览器标签、更多平台与目的地、混合同行人的持续真实验证，以及跨较长周期的真实平台成功率和性能观测。这些属于 1.0 之后的增强，不得由 `1.0.0` 版本号代替验证。
