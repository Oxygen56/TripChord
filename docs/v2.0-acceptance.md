# TripChord 2.0 七轮公共验收

更新时间：2026-08-26
版本：**2.0.0**

TripChord 2.0 表示七轮范围受控的用户能力已经沿同一条正式入口、旅行状态、报价合同、确定性求解和中文行程卡链路闭合。这里的“完成”是功能形态的声明，不是对任意旅行需求的普遍保证。

本页把每一轮的用户结果、可复现依据和声明边界放在一起。证据分为三类：

- **当前来源**：在记录的时间从公开只读接口或已连接来源取得的结果；价格、库存和页面内容会变化；
- **冻结来源**：保存的来源快照，用于离线重复验收；不能替代当前报价；
- **脚本化对照**：固定候选和模型 fixture，用于验证路由或取舍机制；不能证明线上质量。

## 共同验收结论

七轮都复用以下公共边界：

1. 用户从自然语言入口开始，最终结果由 TripChord 的统一旅行状态和中文行程卡返回；不是把内部对象或手工价格直接展示给用户。
2. 日期、人数、地点连续性、价格合同、总价和最终发布由确定性程序复算；模型只能在有界上下文中理解语义、做取舍或提出结构化建议。
3. 当前价格、余位、班次和网页内容只属于本次运行，不进入长期记忆。长期记忆只保存用户确认的稳定/条件偏好，当前请求可以覆盖它。
4. TripChord 永远只查询、比较、校验和建议，不付款、下单、锁位、接受条款、改签或取消预订。

### 版本与证据边界

因此，`2.0.0` 可以准确解释为：**七轮范围受控功能形态完成**。它不等于：

- 任意复杂自由行都能在一次运行中找到方案；
- 所有 OTA、所有目的地或全网最低价；
- 生产用户、生产 SLA、商业采用或跨机器长期稳定性；
- 自动交易、库存锁定或真实预订成功；
- 所有外部 Agent 宿主都已接入；
- 冻结回放中的金额就是今天可购买的价格。

历史 1.0 记录仍保留，因为它是单目的地桌面核心的可复现基线；当前公共版本和能力总览以本页、[README](../README.md) 与 [产品需求文档](product-requirements.md) 为准。
