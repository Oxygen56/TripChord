# TripChord post-training

This directory turns frozen, verifier-checked planning traces into three
separate artifacts:

1. Conversational SFT traces with strict JSON answers.
2. DPO preference pairs where the rejected answer has an explicit hard
   constraint failure or lower global utility.
3. A small pairwise reranker that chooses between local repair and global
   regeneration according to a declared stability/quality preference.

The labels are generated by deterministic synthetic oracles. They are not human
preference data and do not establish real-user quality. Destination groups are
held out as units: groups 0–7 train, 8–9 validation, and 10–11 test. This avoids
putting variants of the same synthetic city in multiple splits.

## Reproduce checked-in data and CPU reranker

```bash
uv run python -m training.build_trace_datasets
uv run python -m training.policy_reranker
uv run python -m training.train_sft --validate-only
uv run python -m training.train_dpo --validate-only
```

The reranker may rank only candidates that already satisfy deterministic hard
constraints. It cannot bypass the Verifier.

## Optional LLM adapter training

```bash
uv sync --extra training
uv run python -m training.train_sft --model <causal-model-id>
uv run python -m training.train_dpo --model <causal-model-id>
```

No base model is silently selected: model license, language support, compute,
and deployment constraints must be decided explicitly. The checked-in evidence
only claims that the SFT/DPO datasets and launch paths validate structurally.
It does not claim an LLM adapter quality improvement until a model run and an
unseen-city evaluation are recorded.
